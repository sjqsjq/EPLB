# workload 变化特征与 adaptive 适用条件 —— 离线分析报告（未启动任何新实验）

日期：2026-10-16。范围：仅离线读取已有校准/五臂战役/crosstab/捕获索引与日志。
配套数据：`timeline_events.json`（25 start 全事件时间线）、`workload_variation_analysis.json`（结构化结论）。

## 一、当前评估工作流到底怎样变化

**1) 构成：不是随机混合，而是 4 个连续域段的顺序切换。**
源文件 `multi_domain/prefill_heavy_universal.jsonl` 本身即 4×4000 按域分块；content-hash 切分保持了各域内的原始顺序。evaluation.jsonl（7963 条）：

| 段 | 请求区间 | n | tokens | token 占比 | 平均 tok/请求 |
|---|---|---|---|---|---|
| sharegpt | 0–1924 | 1925 | 1,344,654 | 15.7% | 698 |
| prover | 1925–3947 | 2023 | 1,028,280 | 12.0% | 508 |
| book | 3948–5931 | 1984 | 2,031,281 | 23.7% | 1024 |
| code | 5932–7962 | 2031 | 4,159,488 | 48.6% | 2048 |

总计 8,563,703 tokens；相邻域切换仅 3 次。cumulative token 边界 0.157 / 0.277 / 0.514，
按 ~370 s 全程折算墙钟约 58 s / 103 s / 190 s（均匀吞吐假设；A00 的 window#–墙钟 r²=0.9999 支持该近似，±数%）。
calibration.jsonl 同构（边界 2075/4052/6068）。

**2) GPU batch 是否混域：无直接记录，明确不可判定（batch 粒度）。** 解析推断：并发 256 →
每个边界只产生一个约 256 条请求（~10–12 s）的双域过渡带；段内 chunked prefill 打包的是同域请求
（prover ~16 条/forward，code ~4 条/forward）。因此“客户端 3 次切域”≈“GPU 工作流 3 个短过渡带”，不是高频切换。

**3) fresh 归一化 logical 专家分布是否持续变化：** cos_sim 探针（相邻窗口原始 all-reduced logical
负载向量的逐层余弦，均值；与 placement、α 无关）——A00（W=16 固定，α=0，5 次启动）全程 cos≥0.9551，
各段均值 0.965–0.995：**段内近平稳**。注意 STABILITY 每 4 窗口才落一条日志，边界上的单窗口阶跃可能
恰好未被采样（A00 的边界窗口 w#10.5/18.6/34.4 均未被记录），故段内平稳可信、边界处不能用 A00 否定阶跃。
边界阶跃的实证来自 D 臂（每窗口都看 ratio 序列）：A01 每次启动都在 frac 0.17–0.23（boundary1 后）
稳定触发 4 个 reset（Δ=0.15/0.465/0.057/0.051，5/5 次启动复现）；A11/P11 在三个边界均有 reset
（frac 0.157–0.22 / 0.28–0.30 / 0.51–0.55）+ 段内额外触发。**各域归一化分布的形状无法给出：
按域路由直方图从未被记录，且全部 18 个 prediction_v1 真实捕获都来自单域数据集
`L512_O1_realprover_n8192.jsonl`——不含 sharegpt/book/code。**

**4) W/reset 变化对应外生变化还是噪声：两者混合，可分离。**
- 外生成分：A01 每 start 首个 reset 锁定 boundary1（Δ 大，0.15–0.48）；A11/P11 的 boundary2/3 reset。
- 噪声成分：A01 后续 reset Δ 仅 0.05–0.07（刚过 0.03 阈值），聚在 prover 短提示段=采样噪声再触发；
  A10（仅 W）每 start ~16 shrink + ~11 grow 分布于所有段、最大 ratio jump（均值 0.27，max 0.49）
  出现在 prover 段内部而非边界；A10 在 prover 段 cos 低至 0.58–0.88，而同 α=0、固定 W=16 的 A00
  同段 ≥0.958 → 该“不稳定”主要是**窗口收缩自致**（8-forward 窗口 token 减半、直方图噪声翻倍），属内生振荡。
- A11 每 start 比 A01 多 3–5 个位于 book/code 段内部的 reset（布局更新/噪声混合）。

**5) 记录不足、不可判定的问题（不推测补齐）：** per-batch 域组成；按域专家分布形状；
边界精确墙钟时刻（仅为吞吐均匀假设下的推断）；窗口长度不同的臂之间 cos 绝对值不可直接互比。

**对齐时间线交付：** `timeline_events.json` 含 25 个 start 的 STABILITY/ADW/RESET/WINDOW/issued/wall/PROF
全事件（时间戳、frac、zone 标注），及按臂×zone 聚合；代表性时间线（eacR1_A11）已嵌入 JSON。

## 二、多域是否存在可利用的追踪空间

四级判别（前三级不蕴含第四级）：

| 级别 | 结论 | 证据 |
|---|---|---|
| 域标签不同 | 是 | 4 连续段、3 次切换、段长 58–190 s |
| 专家分布不同 | 间接是 | 边界 ratio 跳变 +0.15~+0.48、reset 跨启动复现；按域幅度不可量化（无直方图） |
| greedy 布局按域不同 | **未测** | 从未构建过按域布局（需要按域路由计数，不存在） |
| 布局有真实执行时间优势 | **同域实测≈0；跨域未测** | 见下 |

**同域 oracle 界（crosstab_v1 实测单元，行=同域 realprover 3 批次，列=identity+3 冻结 greedy）：**
T_static,cand=min_p Σ_i T(x_i,p) 对比 T_switch,cand=Σ_i min_p T(x_i,p)（K_i 相等）：

| 层 | T_static,cand | T_switch,cand | oracle gap |
|---|---|---|---|
| layer-024 | 4452.0 µs | 4452.0 µs | 0.0 (0.00%) |
| layer-028 | 4392.2 µs | 4391.7 µs | 0.5 (0.01%) |
| layer-044 | 4250.5 µs | 4243.2 µs | 7.2 (0.17%) |
| layer-071 | 4368.9 µs | 4347.2 µs | 21.6 (0.50%) |
| 汇总 | 17463.6 µs | 17434.2 µs | **29.4 µs (0.168%)** |

4 层判决全部 common_static_sufficient、无行追踪自身 base。**范围警示：该结论只覆盖“同域批间变化”，
既不能外推为跨域无空间，也不能因“分布确实随域变”就断言跨域有空间——跨域第 4 级是唯一缺口。**

**成本侧（实测）：** adaptive 净服务成本 A11−A00=+10.40 s CI[+5.00,+15.80]（排除零）；
A10−A00=+4.79 s、A01−A00=+6.45 s（与零相容）；planbuild 39–99 ms/窗口；迁移墙 1.3–2.7 s/次。

**break-even 推算（假设显式）：** 专家执行占服务时间 ~39%（94 层×~1450 µs vs ~350 ms/forward）。
理想收益 ≈ 0.39·g·370 s（g=按域切换相对最优公共静态布局的 K 加权 oracle 收益比例，未计捕获率折扣与切换成本）：
g=0.17%（同域实测）→ ~0.24 s；g=2% → ~2.9 s；g=5% → ~7.2 s（须近乎完美捕获+抑制自致振荡才打平）；
g=10% → ~14.4 s（才可能净赢）。**跨域 g 未知**；叠加“每次运行仅 3 个切换点”“code 域占 48.6% token、
静态布局即可吃到大部分收益”，先验不利但不决定性 → 应先用低成本 Phase A 实测 g，而非直接上服务级实验。

## 三、最小多域验证设计（protocol + budget，未运行，待批准）

### Phase A：跨域捕获-重放 crosstab（CD-X）—— 补第 3、4 级证据
- 捕获：4 域 × 2 层（layer-024 bridge、layer-071 deep，复用既有插桩层）。每域×层：
  calibration 段 1 个捕获（**仅用于构建该域 greedy 布局 L_d**）+ evaluation 段 1 个捕获（**仅作为计时行 x_d**）
  → 16 个捕获单元，真实服务、真实请求、真实 forward（沿用 prediction_v1 捕获协议）。
- 重放矩阵/层：行=4 域 evaluation 捕获，列=identity + 4 个按域 greedy 布局（共 5 列）；
  4 starts × 5 blocks × 50 timed forwards，crosstab_v1 同协议（fresh start 语义、fenced 计时、正确性门同前）。
- 端点：T(x_d,p)；T_static,cand=min_p Σ_d K_d·T(x_d,p)，**K_d 预注册为 evaluation token 份额
  (0.157/0.120/0.237/0.486，来自数据集结构而非任何结果)**；T_switch,cand=Σ_d K_d·min_p T(x_d,p)
  （未来可知的候选集参照，非可部署算法）；行追踪检验=own-vs-other base 配对 CI（ε margin 沿用 22.9 µs 口径）。
- 预注册判据（运行前冻结）：
  - **supported**：≥1 层 K 加权 oracle gap ≥2% 且该层 ≥2/4 行追踪自身 base → Phase B 有价值；
  - **not_supported**：两层 gap 均 <1% → 终止，写入适用条件结论；
  - **indeterminate**：其余（含 1–2% 或追踪不足）→ 终止并如实报告不确定，不升级、不追加。
- 附带：L_d 两两 displacement → 冻结成本模型 C_batch(k) 估算每次跨域切换的迁移成本与 break-even 段长。
- 预算：捕获 ~1–2 h GPU + 重放 ~3–4 h GPU（160 cell-starts，规模≤crosstab_v1 的 192）≈ 1 天内。
- 合规：evaluation 请求只作计时行、绝不进布局构建；域/层/K_d/判据全部先验固定；重放不含控制器，
  不存在域标签/未来信息泄漏问题。

### Phase B（仅当 Phase A=supported 才运行）：配对顺序服务实验
- 请求多重集恒为 evaluation.jsonl 7963 条；3 个预注册顺序（同一多重集）：
  - O1 自然分段（长复用：4 段 ~2000 条、58–190 s/段；即真实采集结构/域分段流量）；
  - O2 中块（500 条/块按域循环 ~16 轮，块时长 ~12–45 s token 尺度；模拟多租户突发/会话混排）；
  - O3 随机混洗（固定种子；batch 级混域、无复用=最不利追踪情形）。
  段长规则由数据集结构与固定常数预先规定，**不按评估吞吐挑选**。
- 臂：F=强固定（W=16, α=0.0, ADW off, D off——即 A00 同配置，来自既有多域校准 argmin，非弱对照）；
  AD=冻结 adaptive（W=16, α=0.5, ADW on, D on——A11 同配置）。**主比较是 policy comparison，
  明确不宣称隔离 D**（AD 同时含 α=0.5 基线差异）；模块臂（A10/A01 配置）不进主矩阵，
  仅当 AD 在某一顺序显著为正时作为预先指定的可选后续（不自动运行）。
- 控制器不获得域标签/未来请求/切换边界（现状即满足：D 检测器只读 ratio 序列）。
- 客户端记录每请求 send/start/end 时间戳（纯客户端，不改服务器代码）→ 离线重建 in-flight 域组成、
  batch 混合度与过渡带；服务器日志照常提供 STABILITY/ADW/RESET/swap/wall 时间线。
- 客户端到达、并发 256、I/O、服务配置跨臂跨顺序全同。
- 5 轮 × 3 顺序 × 2 臂 = 30 starts；轮内顺序按预注册轮转平衡；主端点=完整工作流墙钟 +
  固定口径 token 吞吐（含全部监控/规划/迁移/提交开销）；恢复时间、窗口轨迹、布局质量仅作解释性端点。
- 统计（预注册）：每顺序内 AD−F 按轮配对，t-CI df=4；成功=O1 或 O2 的 CI 排除零且为负（O3 如实并列报告）；
  失败/不确定=任一 CI 跨零或为正 → 结论写“该模型/硬件/工作流类上 adaptive 层未证明净收益”，
  结束，不做显著性驱动追加；失败 start 退役不重试；不挑 best start。
- 预算：30 × ~12 min ≈ 6 h GPU + ~1 h 分析。

## 四、交付四项

**(a) 当前工作流有无明显可追踪变化：** 结构上有、但稀疏——每次运行仅 3 次外生域切换（长段 58–190 s），
边界处负载形态确有实跳（ratio +0.15~+0.48，跨启动复现）；段内近平稳（A00 cos≥0.955）；
控制器实际检测到的“变化”多数是 prover 短提示段的采样噪声被自适应窗口收缩放大后的自致振荡
（A10 同段 cos 0.58–0.88 vs A00 ≥0.958）。

**(b) 多域能否改善 adaptive 相对表现——证据与反证：**
支持：① 边界处分布实跳且可复现检测；② 段长远大于迁移墙（58–190 s vs 1.3–2.7 s），切换成本原则上可摊销；
③ 域 token 权重悬殊（code 48.6%），按域特化理论上存在差异化收益空间；④ 检验工具（crosstab 重放管线）现成且便宜。
反对：① 第 4 级证据唯一实测处（同域）oracle gap 仅 0.168%，行不追踪自身 base，4/4 层 common_static_sufficient；
② 每次运行只有 3 个切换点，完美追踪者可利用的事件极少；③ adaptive 实测边际成本 +4.8~+10.4 s，
已高于 g≤5% 情形下的理想收益估算（0.2–7.2 s）；④ 检测器大量在噪声上触发（自致振荡），实际捕获率必然打折；
⑤ code 占一半 token，一个（按多域校准的）静态布局无需自适应即可吃到大部分可能收益；
⑥ 跨域布局优势完全未测——举证责任未尽，不能预设多域实验会让 adaptive 获胜。

**(c) 最小实验矩阵/段长依据/预算/成败判据：** Phase A（16 捕获单元 + 160 重放 start，~1 GPU 日，
预注册 gate：gap≥2% 且 ≥2 行追踪 → supported；<1% → not_supported；其余 → indeterminate 终止）；
条件性 Phase B（2 臂 × 3 顺序 × 5 轮 = 30 starts，~6 GPU 时；O1 长=真实分段结构、O2 中=500 条租户突发尺度、
O3 短=均匀混合最坏情形；成功=O1/O2 内 AD−F CI 排除零为负；否则终止并记录适用条件）。

**(d) 现在不需要的实验：** 五臂/大矩阵在多域上重跑；gating G 实现与验证（已决 document-only）；
BI planner 后续（E-P 已答：不更优、不更省）；重排工作流上的 W/α 网格再校准（W*=16/α*=0 直接作 Phase B 固定臂）；
identity/ILP 参考重跑（用户规则豁免）；延迟/floor/gate 类机制实验（已关闭）；合成路由研究（范围禁令）；
gate 未通过前任何跨域捕获规模扩展。
