## 0. 为什么必须重校（仅陈述原因，不预告收益）

- F1 修复改变了 z 的信号空间（物理槽 → 逻辑身份），κ 与 z 带的旧数值
  对新信号无定义，必须联合重拟合（规则 FORM 与 step-5 §3 相同）。
- F2 把 θ 从"窗累计计数"改为"工作量占比 rate"。旧 θ 数值校准自
  W=16 单一窗长（calibration_plan_v2.md §1"整程 W=16 by construction"），
  对 W∈{8,32,64} 有系统性尺度偏置（2026-10-16 审计：raw h_w 中位数
  0.62M@W8 → 1.89M@W32，约 3×）。rate 尺度下需跨 W 合并重校。
- 本方案**不声称**重校后性能更好；也不把旧 v2 的正式比较结果归因于
  上述偏置。

### 1.2 运行失败政策（r3 预注册）

- **通信器级致命错误**（任 rank 的 det SUM 或确认 MIN/MAX 集合通信
  本身异常）：控制器 FATAL 日志 + 尽力而为写入
  `{"event":"fatal_collective","phase":1|3,…}` 记录 + re-raise →
  scheduler 进程终止 → 本次运行结束（框架故障传播/作业重启流程
  接管）。这是**终止**语义：可疑通信器上不再进行任何普通确认或
  提交。恢复 = 重建通信器 = 作业级重启，不是控制器职责。
- **健康通信器上的相 2 本地异常**：共同 HOLD（rollback + 错误哨兵 +
  prop_valid=0 归约），连续 2 次失败 → 冻结于 W_init（继承 v2 安全
  模式），服务继续。
- logging run 因 fatal_collective 终止 → 该启动**无任何拟合样本**，
  属基础设施失败（非结果）：允许该槽位重启**一次**（记录在案）；
  5 次启动预算内出现**第二次**致命终止 → 停止校准并报告，不追加。
- 非致命原因的中断（人为、断电等）同此政策：重启一次、记录在案；
  任何重启都不改变 §2–§4 的规则与门槛。

### 1.3 预算（显式工作量口径，r3 修订）

- **5 次 W0 启动** = 4 logging（W∈{8,16,32,64}）+ 1 行为验证（§5）。
- 每次启动的工作量：**1 遍 W0 = 8037 请求**（≈8.45–8.65M 输入
  token，≈1032–1056 个 forward，服务墙钟 ≈365–370s；启动/预热/
  JIT 在计时块外，约 8–15 min）。5 次启动合计服务墙钟 ≈31–35 min，
  含启动约 1.5–2.5 h 总墙钟。
- "5 次启动"**不自动等于**任何历史战役的工作量：本节数字即其
  完整工作量定义。不含任何跨臂比较，不是性能战役。

### 2.1 拟合样本定义（r2 新增，r3 更新协议号）

**合格窗** := `committed==true` 且 `protocol_rev=="r3"` 且
`event ∉ {init, uncertain_carry, uncertain_hold, forced_shrink_uncertain,
confirm_hold, confirm_fail_freeze, w_desync_freeze, fatal_collective}`
且 `z != null` 的窗。
κ/z 带/θ_r 的全部拟合样本（Z_s、Z_c、H_rate_s、N_s）只取合格窗；
HOLD 窗与不确定窗不进入拟合（其 z/h_rate 或对应被作废的提案、或对应
未更新的 ref，语义与正常窗不同）。logging run 的惰性 knob 设计保证
除 init 外几乎全部窗为合格窗。
**r3 移除"每 run ≥30 合格窗"规则**——它与 W64/W32 的数据长度不相容
（见 §2.2），代之以按用途的样本规则；这是开跑前的预注册修订，
**不开跑后降门槛**。

### 2.2 样本量预注册（r3，W64 冲突的解决方案）

**窗口数算术**（由已知工作量事实推出，非新数据）：W0 一遍
≈1032–1056 forward → 窗数 ≈ floor(forwards/W)：

| W | 窗数（预期） | 扣 init+护栏后合格静止窗（预期） |
|---|---|---|
| 8  | 129–132 | ≈104–107 |
| 16 | 64–66  | ≈51–53 |
| 32 | 32–33  | ≈25–26 |
| 64 | **16** | **≈12** |

（护栏 ≈18.4% forward：3 边界 × ±250 请求 ≈ ±32 步；实际数以
记录为准并如实报告。）

**选定方案 B：保留原请求预算（每 run 1 遍 W0），按用途重设样本
规则，并显式规定 W64 能拟合什么、不能声称什么。**

按用途的样本规则（全部预注册，开跑后不改）：
1. **κ / z_lo / z_hi**：合并 4 个 run 的合格静止窗 Z_s 池拟合。
   **门：池 ≥ 150**（预期 ≈192–198）。不足 → "样本不足"，停止拟合
   并报告，不放宽。
2. **z_urgent**：合并 4 个 run 的伪切换窗 Z_c。**门：池 ≥ 20**
   （预期 ≈45）。不足同 1。
3. **θ_r_low/θ_r_act**：合并 4 个 run 的合格静止窗 H_rate_s 池取
   p30/p60。**门：池 ≥ 150**（与 1 同池）。同时**逐 W 报告**中位数
   与 n（W64 的 n 预期 ≈12，如实标注小样本）。
4. **W64 run 的预注册用途**（能声称的）：
   (i) 机制在 W64 下正常运行（窗被记录、协议健康、无 desync/
   freeze/fatal）；(ii) 其合格窗并入 1–3 的池（每窗都是有效的
   rate/z 样本，与 W 无关）；(iii) §4 G1-D 跨 W 诊断中 n≈12 的
   一个诊断点（显式标注小样本）。
   **W64 不能声称的**：任何 W64 单独的分位数/中位数作为独立估计、
   任何需要 W64 单 run n≥30 的门或结论、任何"W64 下校准通过"的
   单独表述。
5. 实际合格窗数比预期低 >30%（且非护栏算术原因，如意外 HOLD 风暴）
   → 停止拟合、报告并排查，**不降门槛、不追加启动**（追加 = 新
   预注册）。

**方案 A（未选定，备查）**：若坚持"每 run ≥30 合格窗"，W64 需
≥37 窗 → ≥2368 forward → 预注册 **3 遍连续 W0**（3×8037=24111
请求，服务墙钟 ≈1100s ≈18–20 min，另加同额启动开销；总预算变为
5 次启动但 W64 槽位工作量 ×3）。注意：同一请求文件的重复遍之间
窗样本**相关而非独立**，≥30 的计数意义主要是分布估计而非独立性。
选定 B 的理由：G1 已降级为诊断（§4），不再有任何门需要 W64 单
run 样本量；池拟合不需要 W64 单独充分；A 以真实预算购买相关
样本，与预算冻结纪律相悖。如用户改选 A，本段即其预注册文本。

## 3. 拟合规则（FORM 与 step-5 §3 相同，数据换新）

对 4 次 logging run 的**合并**样本（池门槛见 §2.2）：

1. `κ = median(Z_s)`（全部 W 的合格静止窗合并；Z 为逻辑空间 z 序列，
   即用 κ=1.0 记录的 s_change 换算 z = s_change·n_layer/κ_run，
   κ_run=1.0，故 Z_s 直接由 s_change_logical 与 n_fresh 重构）。
2. `z_lo`、`z_hi`：对 step-5 §3 的同一 p90/p99 重标度公式，作用于新
   Z_s（公式逐字沿用 calibration_plan_v2.md §3，仅数据替换）。
3. `z_urgent = max(3·z_hi, p50(Z_c))`。
4. `θ_r_low = p30(H_rate_s pooled)`，`θ_r_act = p60(H_rate_s pooled)`
   —— 合并 4 个固定 W 的合格静止窗 rate 样本（F2 的实质：阈值定义
   在公共工作量占比尺度上，跨窗长可比）。
5. 其余 knob：规格默认值（见文首），不拟合。

拟合盲态：先按 §2 分类并锁定窗清单，再一次性算出 6 值；不允许看
任何正式比较数据迭代。

## 4. 验收与诊断（r3 重设被测命题；失败=如实报告并停下，不静默调参）

> r3 修订说明：r2 版 G1/G4 以跨 W 比值和 swap 窗 z 作**门**，存在
> 评审指出的混杂——(a) 不同 W 产生不同布局历史，真实余量可以合法
> 不同，跨 W 比值不构成对尺度不变性的有效检验；(b) 真实需求变化
> 引发的 swap，z 本应高，"swap 窗 z ≤ z_lo"把真需求信号误判为 F1
> 失效。r3 将两命题的**验收**移到无混杂的受控测试上，logging 数据
> 只做预注册解释带的诊断/上下文报告。这是测量前修正被测命题，
> 不是降低性能成功标准。

### G1 尺度不变性（F2）

**验收（门）＝同一状态成对缩放测试：**
- **PT1（机制级，离线，已实现=T5/T6b/T7）**：同一控制器状态与同一
  输入序列，(h,n)→(c·h,c·n)，c∈{0.5,1,2,4,8} → 决策轨迹逐一相同；
  rate-θ 下不同工作量尺度决策相同（对照：冻结 v2 raw-θ 在同 rate
  不同尺度下决策分裂）。冻结前对最终源码重跑，须全 PASS。
- **PT2（数据驱动成对检验，logging 后、离线、预注册）**：对 4 个
  run 的**每个**合格静止窗，取记录的 (h_w_assignments,
  n_fresh_assignments)；构造缩放对 (c·h_w, c·n_fresh)，
  c = median(W64 run 的 n_fresh)/n_fresh_window（把每个窗映射到
  W64 工作量尺度）。断言：重算 h_rate 与记录值**逐窗完全相等**
  （算术恒等），且冻结决策函数在相同 z/状态代理下决策**逐窗相同**。
  **门：100% 恒等；任何 mismatch → F2 实现缺陷 → 停止，不冻结。**
  （PT2 的实质是回归防线：证明决策路径只经由 rate，没有任何位置
  偷用 raw h_w。）
- **G1-D（诊断，非门）**：4 个固定 W 的合格静止窗 h_rate 中位数
  m_8, m_16, m_32, m_64 及 max/min 比；同批窗 raw h_w 中位数之比
  （预期 ~3–8× 跨度，F2 修复前后对照存档）。**逐点报告 n**
  （W64 预期 n≈12，标注小样本）。预注册解释带：比值 ≤1.5 与 F2
  相容；1.5–3 → 报告并做离线分段排查（布局历史混杂是合法解释，
  排查记录归档）；>3 → F2 有效性威胁：**冻结前停下**，报告。
  解释带只影响"是否停下排查"，不回写任何 knob。

### G2 分离度

p50(Z_c) > z_hi；否则如实报告（同 step-5 规则）。

### G3 重尾

p90(Z_s)/p50(Z_s) > 10 → 报告（不自动处理）。

### G4 逻辑身份不变性（F1）

**验收（门）＝受控离线测试（无真实需求变化混杂）：**
- **T2**：窗中 swap 后 det 累计器按 commit 点位镜像重映射，窗口末
  logical gather 与 oracle 逐元素相等（部分窗内 swap 场景）。
- **T3/T3b**：同一逻辑工作量跨 swap → 逻辑空间 s_change≈0
  （z≈3e-5），对照物理槽空间 s=0.2942（z=147，v2 伪影复现）。
  冻结前对最终源码重跑，须全 PASS。
- **swap 窗 z 不再设门**（真实需求变化引发 swap 时 z 本应高）。

**logging 数据的角色＝按上下文报告（诊断，解释带预注册）：**
- 每个合格 swap 窗报告：{触发事件/前置决策、离线段分类（静止/
  伪切换）、swap 窗 z、其后 1–3 窗的 z 轨迹}。
- **D1**：R_swap = median z(swap∩静止段) / median z(非swap∩静止段)，
  两侧报 n（合并样本 <5 则只列点值不报比值）。预注册解释带：
  R_swap ≤2 与"F1 生效+静止段内仍有真实漂移"相容；>2 → 冻结前
  排查（对涉事窗离线重构 F1 映射路径），排查记录归档；不静默
  通过，也不事后挪带。
- **D2**：swap 后 z 回落比例 = {3 窗内 z 回到 ≤z_lo 的 swap 窗} /
  {全部合格 swap 窗}（报 n；伪切换段的 swap 天然伴随高 z，按段
  分层报告，不作失败判据）。

### G5 κ 跨 run 稳定性

每个 W 单独拟合的 κ 与合并 κ 之比 ∈ [0.5, 2]（报告项；W64 单 run
样本 n≈12，其单拟 κ 标注"小样本，仅列示"）。
