## 2. E3 深挖: 赢在哪、输在哪 (formal 8+8 boots, per-request)

**TTFT 分布 (s)**: P p50=**5.57** / p90=6.86 / p95=7.63 / p99=10.69 / max=17.4; I p50=6.09 / p90=6.42 / p95=6.77 / p99=7.99 / max=9.3。
→ **中位数 P 赢 8.4%** (放置改善对典型请求真实有效); **尾部 P 输** → GOOD@1.0 0.889 vs 0.949 (−6.0pp)。

**尾部 100% 由 swap 窗口光环造成** (按请求服务中点到最近窗口发起时刻的距离分桶):

| 距窗口 | n | p50 | p95 | p99 | 超参考率 |
|---|---|---|---|---|---|
| 0–3s | 26508 | 6.01 | 8.14 | 10.87 | **20.4%** |
| 3–8s | 15011 | 5.51 | 7.77 | 14.18 | 8.8% |
| 8–20s | 23454 | **5.31** | **6.15** | 7.27 | 2.3% |
| >20s | 563 | 5.37 | 5.47 | 5.52 | 0.0% |

距窗口 >8s 的请求 p95=6.15, **优于 I 臂全局 p95=6.77**。即: 若无光环, P 全面赢。

**窗口太密**: E3 run ~200s 内发起 13–16 窗 (每 ~14s 一窗), 0–3s 光环覆盖 40% 请求, 光环互相叠加 → 稳态 GOOD 仍差 (t>40s: P 0.897 vs I 0.941)。

**Ramp 成本**: 前 40s P=39.8 req/s vs I=43.8 (首窗在负载 ramp 期即发起); 稳态 P=**43.9** vs I=41.4 (**+6.0%**)。总 tps 增益 +2.7% = 稳态 +6.0% − ramp 损失 − 尾部拖累。

**自适应几乎没动**: S/H/W=1/16/16 占 244/256 日志行; S=4/W=64 仅 12 行 (2/8 boots, 瞬态)。采样门 recording_ratio 1.3% → 控制信号饥饿 (与资格裁定 S>1 share=0 一致)。

## 3. 新系统的优势 (证据背书)

1. **可靠性是独占优势**: v2 是唯一能在 campaign 配置下跑完的版本 — 64/64 formal + 全部 ad-hoc, 327,680 请求 0 错误 0 watchdog; gh_pristine async + campaign controller 组合确定性死锁 (B1 签名), FIX-3 按 peer 升序分组是死锁自由的根因修复, 同步成本已如实保留 (22.4–26.4ms/300ops)。
2. **稳态吞吐 +6.0%** (E3 主场, 对 identity), 且 formal 预注册分析 tps +1.14 p_H<1e-4 — 统计上站得住。
3. **中位延迟 −8.4%**: 放置质量对典型请求真实改善, 老系统无此数据可比性 (无 per-request 全量记录)。
4. **确定性与可审计性**: 同配置三轮机制计数逐窗一致 (E3 paper: 11 窗/1911 swap/7 reset × 3 轮), decision/plan hash, 镜像对称 5706 对全过 — 本次根因分析数小时即闭环, 全靠这些设施。老系统不具备。
5. **对老代码的绝对增益**: campaign flags 下 v2 E3 ≈43.1–44.1 vs gh 38.5 — v2.1 机制+采样门在同配置下值 ~+12–14% 绝对 tps。
6. **自适应机构在位、只是饥饿**: S/H/W 状态机确实行使过 (2/8 boots S=4), 瓶颈是信号供给, 不是机构缺失 — 可调。

## 4. 可调整点 (全部为新版本 v3-dev 候选, 按预期收益排序)

- **A. 窗口节奏化 (最大杠杆)**: 把"每 14s 一窗"改为最小间隔约束 (如 ≥20s) 或按扰动预算合并小窗。预期: 0–8s 光环覆盖从 ~63% 请求降到 <25%, Goodput 缺口 −6.0pp → 收窄至 −1pp 内, 稳态 tps 增益保留。风险: 窗间放置陈旧度上升; 需 A/B 验证。
- **B. Ramp 期延迟首窗**: 队列深度/在飞请求低于阈值前不发起首窗 (或首窗只 plan 不执行)。预期: 收回 ramp 4 req/s 损失, 总 tps 增益 +2.7% → 向稳态 +6.0% 靠拢。
- **C. 双速率采样解饥饿**: 控制信号用轻量高速率通道 (计数/熵), 详细 tracer 保持 1.3% 低速率。预期: S/H/W 真正行使, 解锁已设计的自适应; 资格门 S>1 share 有望过 0.10。成本必须入账 (高速率通道的开销如实保留)。
- **D. z 阈值工作负载相对化**: z_hi=314 对 freq6 类负载 (z 峰值 94.3) 永不触发 → 以 warmup 期 z 分位数或流上自动校准替代固定值。属跨域增益恢复的关键; 需独立 cell 验证, 不与 A/B 混包。
- **E. ROI 负值止损 (E4 类)**: probe 窗测得 swap ROI ≤0 → 冻结放置 (standby), 把 E4 −7.9% 变为 ~0%。注: 这不是"禁用迁移掩盖问题" — E4 损失已如实报告, standby 是新版本的控制律特性, 需预注册+独立台账。
- **F. 不建议动的**: FIX-1/2/3 同步路径 (死锁自由证明在身, 成本小且必须保留); headroom θ 单独调参 (与 D 耦合, 避免变相参数搜索)。

## 5. 建议的执行顺序 (待作者批准)

1. **Phase B (零 GPU)**: v3-dev 分支实现 A+B (+C 设计稿), 离线确定性套件 + j4/j5 canary 复跑; 不部署到冻结 DEP。
2. **Phase C (GPU, 需预算批准)**: 预注册包 — E3 主场 v3-dev vs v2 vs I (I 臂是否复用既有 8 boots 由作者裁定, 默认新跑不混池); 建议 ≤24 boots。成功判据预注册: E3 Goodput@1.0 缺口 ≥50% 收窄 ∧ tps 增益不降。
3. **Phase D (GPU, 独立包)**: D+E 候选各配 freq6/E4 cell, ≤16 boots, 另行预注册。
4. freq6 跨域增益声明仍按 ONEPAGE A2/A3 边界执行, 任何 v3 结果不回填 v2 池。
