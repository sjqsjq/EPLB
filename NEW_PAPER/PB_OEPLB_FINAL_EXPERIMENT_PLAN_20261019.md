日期：2026-10-19。性质：论文实验设计与执行交接草案，尚未执行；不是已冻结的新战役。以单节点8×H20、Qwen3-235B-A22B-FP8、EP=8为主，遵守作者“先覆盖整个第五章，不再只围绕自适应反复调参”的要求。本文的identity即作者此前写的identify。

**目标：用同一套可复现证据回答三件事——统计是否可信且划算，增量规划是否有独立作用，整个PB-OEPLB相对identity和官方SGLang EPLB是否具有部署价值。自适应是否优于强固定是独立问题，不能由系统整体收益代替。**

## 1. 怎样判断目前“消融效果太低”

目前rev1相对原策略证明了有限控制行为改善，尚未建立稳定时间优势。裸阈值退出减少是规则遵守证据，不自动证明低误报率；状态驻留增加也不能替代端到端收益。若它作为“自适应带来显著加速”的消融，证据不足；若作为“确认与滞回怎样改变控制行为”的机制实验，则有作用。

严格说，原v1与rev1同时改变了退出条件、确认和回退路径，属于版本对照，不等于把一个模块单独拿掉的完整消融。新方案中的P对F、P_denseSample及其他单模块替换才分别回答相应机制的必要性；仍须按实测结果决定能否声称性能贡献。

因此不能把下一步理解为寻找更容易获胜的数据集。应当补齐研究一和研究二的匹配对照，再以当前冻结的完整系统与强基线同场比较，并保留固定PB参照。若PB整体有收益而自适应不优于固定，论文分别报告两者；若自适应仍不确定，不把整体收益归给它。

研究内容主要依据保持不变：O4→阶段感知统计；O1/O2/O3→有限增量重平衡；O5→自适应节奏，O3/O4为控制提供输入与约束。

## 4. 主对照臂与公平性

### 4.1 四个主臂

| 标签 | 精确定义 | 作用 |
|---|---|---|
| I：Identity | 自然专家映射，PB与EPLB均关，无后台重放置统计 | 最低控制开销的真实基线 |
| E：SGLang-EPLB* | 官方在线EPLB，校准候选集合中选出的算法/R/周期 | 强公开实现对照，含全部recorder、规划、迁移开销 |
| P：PB-OEPLB-final | 当前rev1完整冻结系统 | 论文主方法，含全部真实开销 |
| F：PB-fixed* | 相同统计/规划/接受与预算，关闭自适应状态，固定S/H/W | 分离PB整体收益与自适应附加价值；F仍会在线调整布局 |

I、E、P是用户要求的核心三方，F是避免夸大自适应所必需的参照。Frozen-ILP、离线最优候选或历史EPLB静态布局可另作参考，不取代E或F。

### 4.2 校准候选，避免故意使用弱EPLB

只使用独立校准请求，正式评价前冻结。一个有界候选集合为：

| EPLB候选 | 算法 | 冗余总数R | 重平衡迭代周期 |
|---|---|---:|---:|
| e0 | auto→deepseek | 0 | 64 |
| e1 | auto→deepseek | 16 | 64 |
| e2 | auto→deepseek | 32 | 64 |
| e3 | deepseek_vec | 16 | 64 |
| e4 | auto→deepseek | 16 | 16 |
| e5 | auto→deepseek | 16 | 256 |
| e6 | auto→deepseek | 16 | 1000（默认周期参照） |

每候选2次校准启动，共14次。deepseek_vec及各R的当前路径合法性先由源码与smoke确认；不可用候选标为unsupported并保留原因，在评价开始前冻结可行集合，不以测得较慢为由剔除。层chunk、recorder buffer、触发阈值和dispatch策略固定为该版本的事前规则并完整记录，不隐含再做多维搜索。

F候选为(S,H,W)=(1,16,16)、(2,16,32)、(4,16,64)、(1,8,8)，每格2次，共8次校准启动。以相同α、规划器及预算执行，关闭自适应触发，保持必要统计但不额外计算无用途变化信号。若任一固定档位未实现，先给出明确机制构造，不用“惰性knob”掩盖仍在变窗。

校准流为真实内容的混合阶段/分段组合，覆盖稳定与变化、短输出与长输出，组成在计时前冻结。第一阶段22次筛选后，各取E/F前两名；第二阶段在独立的校准确认内容上，每个候选再跑2次，最多8次。只用第二阶段平均完整墙钟从各自两候选中选E*/F*；总上限为30次。平局规则先定，例如精确均值相同才按更小R/较简单设置处理。不据终点继续复选到满意。

这种有界复核用于降低单次/少次argmin抽中噪声的风险，不消除选择不确定性。报告两阶段全部原始值及候选集合，E*/F*只称校准选出的设置，不称全局最优；正式比较首次在test上重测。

当前PB参数保持冻结，不用新评价结果重拟合。各方法允许访问同一校准内容；研究历史的调参预算不同应披露，不能宣称所有方法历史搜索成本严格相同。若已有同版本、同候选、同校准协议的合格数据可复用，先列明；30次是两阶段上限，不是必须重复所有历史校准。

### 4.3 共同执行条件与资源约束

- 使用同一SGLang wheel与共同补丁文件，所有臂保持TP/DP/EP、kernel、精度、chunked-prefill、最大running请求等一致。PB/EPLB二选一，I二者皆关。
- 默认保持当前CUDA Graph配置及Radix Cache关闭。EPLB所有候选在所选DeepEP模式下要经过实际请求smoke；不能只引用注释认定兼容。共同模式若无法运行，先标出原因，不能只为某臂关graph后称严格同配置。
- 主表采用共同可运行的执行路径和共同KV token上限，事前设为所有可行臂均可支持的容量；总物理GPU和HBM预算相同。E可有额外专家副本，不强迫它使用PB的无复制算法。
- 额外报告各臂权重、临时峰值、实际KV池和空闲HBM。对“无复制带来更多可用KV”的部署收益，使用第10节原生容量压力实验回答，不在共同KV主表中混作纯规划效果。
- EPLB不同R会同时改变专家执行、dispatch和内存，不假定流量按副本数均分；需观测物理槽/rank实际assignment。
- `--enable-eplb`等参数名以0.5.6.post2为准，完整命令由执行AI从当前解析器生成，不复制最新网页默认覆盖旧栈。

## 5. 数据集与四个最终主实验

### 5.1 真实数据与拆分规则

当前可用池包括domain_switch_160k、multidomain、fixeddata、frozen_requests_500/hellaswag/in2048/longbench_4k/prefill_heavy/real_production/short_in_long_out，以及已有calibration/evaluation和W1/W2。先做CPU清点，列明来源、prompt与token长度、标签及唯一内容数。

旧W1仅125唯一prompt重复32次，旧W2为250×32，不能继续当成高独立性的新主测试。原样保留为已知回归；新主数据优先从较大真实池按内容去重，冻结calibration/test内容级不相交拆分。ID不同不等于内容不同；在截断和模板处理后再检查输入token序列哈希，避免不同长文本截出相同输入。

数据选择只看来源、长度、域和内容哈希，不看PB时间或哪个方法获胜。某域唯一内容不足时，在冻结前调整目标N并登记，不用重复32次补成“独立请求”。工作流中的请求也不作为独立性能重复，统计n仍是服务启动/block。

控制长度时用真实文本token窗口，注明为“真实内容构造的受控请求流”，不称自然生产分布；不合成top-k路由。所有臂接收同一文件、顺序、采样参数与并发。域标签仅供离线分析，不进入控制器。

### 5.3 统一主终点和次终点

| 指标 | 定义 | 用法 |
|---|---|---|
| 完整服务墙钟T | 统一客户端起点至最后请求完成，含所有真实在线成本 | 单一主终点；具体起点随客户端代码锁定 |
| 输出token吞吐 | 实际completion token总数/T | 与主终点并列；O1时数值等于req/s |
| 输入/总token吞吐 | 实际prompt token数/T；(prompt+completion)/T | 分别命名，实际处理与缓存命中另报 |
| TTFT p50/p95/p99 | 请求实际发出至首token，流式客户端时间戳 | 尾部与响应；不由总时间/N推算 |
| TPOT/ITL | 仅O>1，按请求记录后固定汇总规则 | 区分逐token ITL与请求级平均TPOT，不能混池 |
| 完成率/错误/超时 | 所有计划请求为分母 | 方法性失败必须报告，不能只分析幸存成功请求 |
| 实际负载 | 逐层r的跨层mean、分布与max；padding仅在可获得真实形状时算 | 解释指标，不替代主终点 |
| 控制与迁移 | 真实forward、record调用、状态驻留、规划/交换批次/专家对数 | 区分计数单位，不能把未触发的动作记作节省 |
| 资源 | 权重/缓冲峰值、实际KV token容量、队列/在飞请求 | 解释容量差异及压力范围 |

性能请求记录实际token用量；不再遗漏prompt token。闭环并发下客户端Semaphore排队与发送后的服务延迟分别定义，不将客户端等待混成服务器TTFT。对于固定流，吞吐与T是相关派生指标，不当两份独立获胜证据。

请求j的TTFT=t_first,j−t_send,j；输出数O_j>1时，请求级TPOT=(t_last,j−t_first,j)/(O_j−1)。先形成每请求统计，再报告跨请求分位数及跨启动变化。若SSE一次合并多个token而无逐token时间，不能将chunk间隔叫真实ITL。吞吐增益T_ref/T_P−1与时间减少1−T_P/T_ref分别命名。

## 6. 三个研究内容的核心机制实验

### M1：统计正确性、逻辑身份与覆盖

**问题。** 记录的是谁、在哪个阶段、是否对应正确映射？

复用已有最终代码对应的逻辑/物理置换、归约不重复累加、缺样本、共同提交与故障边界测试。CPU测试之外，仅对尚未被最终版本覆盖的GPU路径补小规模验证；不重新跑完整故障战役。

必查：记录许可在对应forward生效；always_record不会绕过稀疏门；负ID/无效行不计；跨交换统计身份守恒；检测ref不随位置改变产生伪突变；全rank按同一通信日程。保存输入、映射、输出及版本。正确性只给正确性结论，不计作吞吐消融。

### M2：阶段感知统计是否足以支持有用的布局

**问题。** prefill计数与decode相关，不代表由它生成的布局一定适合未来执行。

在独立校准/评价内容中，以identity诊断运行捕获四域、prefill与early/late decode的真实路由，使统计比较使用相同输入，不先受不同放置策略反馈影响。对同一校准请求段分别形成prefill-only、all-phase及decode-only统计，以同一规划器、初始映射和预算生成候选；decode-only作为信息诊断，不默认成为在线主臂。

统计比较分两种，不能混淆：一是在相近assignment覆盖下比较信息质量，二是在实际服务出现频率下比较真实成本和最终策略。记录样本规模、prompt覆盖和时间跨度。all-phase提供更多样本时，不能将差异全部归因于阶段本身。

候选仅由校准生成，在后续评价路由/hidden states上测量，不能为每个评价capture单独生成“自身最优”再称预测。轻量直方图可覆盖94层；重权重回放优先复用现有024/028/044/071四层，明确这是有限层证据，不声称全模型oracle。

输出：阶段相关性、候选在未来路由上的rank负载、同一路由真实执行时间及候选选择regret。没有对应decode执行路径时，只报告信息诊断，不用normal prefill replay假冒decode kernel时间。E4中的A1补充在线完整服务验证。

### M3：记录、聚合、规划和迁移的成本覆盖

**问题。** 工作调用减少后，哪些CPU/GPU工作真正减少，哪些影响服务？

主运行只保留低成本日志。另在E1/E4各选一个预声明诊断片段，对代表方法采集有限全8-rank trace，建议总量不超过4次诊断启动；不能用profiler运行替换无profiler主表。

分别标记CPU派发区间、GPU scatter核、归约、CPU planbuild、权重传输与提交等待。不要逐层加cuda.synchronize，不以每层热路径event改变被测程序。事件/trace采集的自成本和范围单列。

输出每类调用数量与可识别执行区间。跨rank不求和当服务成本；GPU并发核时长也不直接相加成关键路径。无法识别的暴露保留unknown，不给“record≤0.5%”等未经识别的上界。A1/A3/A4的净策略差也不作为单个核成本。

### M4：差额引导与纯贪心的同输入比较（老师要求）

比较规则必须明确：G_maxdelta为在相同合法热冷候选中优先取最大负载转移；PB_gap为当前快速/差额两分支；BI为best-improvement搜索参照。不能把一个失败就整层放弃的弱实现作为唯一纯贪心。

共享层选择、rank合法性、接受δ_r、初始映射、剪枝/失败处理及外循环预算；只改变候选选对规则。若某基线本来具有不同搜索集合，另外报告，不能声称只差一行。BI更大候选搜索的CPU时间必须计入。

先在所有合格的已观测负载快照上CPU比较：接受轨迹、最终r、预算使用、模拟候选数、planbuild、移动字节数。这是给定输入的局部优化能力，不单独声称前瞻预测。预算取{32,64,128,300,600}只作离线敏感性，不根据评价计时选主预算。max_swaps_per_layer若未真正使用，不能当有效匹配条件。

再选最多8个预先确定评价capture（四域各2个，选择按时间顺序/哈希，不按获胜幅度），每个比较identity与三种候选。每capture最多3次独立replay启动，同进程内轮转候选顺序；技术重复先在启动内汇总，不能把数千计时forward当独立n。若四层分开运行则单独列出job数，不把24个capture启动偷换为96个层启动。

前瞻回放的布局只在前段校准材料生成，后段评价capture不参与选图、规则或主预算。若另外用评价capture自身计数做同路由what-if，单列为局部优化诊断，不称未见路由预测或在线可达oracle。输出真实执行收益、计划成本和选择regret；更低r不自动获胜。A2再回答在线反复重规划下的净效果。

### M5：预算、停止与可回收机会

优先复用既有前缀收益、最后一步、624迁移数据和停止研究。新版本若权重规模、批量迁移方式或后端变化，先核对成本是否仍同范围，不直接套旧毫秒值。

绘制预算—代理改善—真实时间—移动字节曲线，报告早期大动作与近均衡细调。回本用同一层/同一forward口径q与C，K明确为复用次数；跨域收益变化时用Σq_t−C，不用token份额机械换成服务收益。

“取消预算”只有在主方法实际启用了相应经济预算时才有意义。不能关闭防死锁/防OOM硬上限制造失败；也不能消融一个从未触发的门后宣称无用。当前若只有计算和安全硬预算，论文按该事实写，不新增一个未实现的精确收益门凑消融。

### M6：自适应机制范围

复用v2.1正式对照、原联动和rev1开发比较，各自保留版本。rev1支持规则与驻留改善，未证明稳定时间收益；8次P1稳定grow不能当8次漂移检出，切换段P3回TRACK与高z漂移路径分开。

新主实验记录每次启动的首个统计draw、真实forward及采样状态，不以跨boot同轨迹为入选条件，不按draw事后排除。阈值不再拟合。若强调某分支“无误报/及时检出”，需要真实变化标签与覆盖定义；只有规则触发日志时降低措辞。

## 8. 统计设计、重复数与精度

### 8.1 重复与执行顺序

独立实验单位为新服务进程启动；同条件同block配对。建议8个完整block，条件顺序和臂序事前生成受约束随机轮转表，尽量平衡位置和前驱；5/6臂不能宣称8轮恰好实现完整拉丁方。保存seed、实际起止与执行位置。

同一个请求流在各block固定，不能既换内容又不记录。新内容泛化与随机采样的广泛总体主张需额外独立请求流，本次只覆盖冻结工作流。请求、层、窗口、swap或token都不是性能n。

### 8.2 主比较与多重性

单一主终点仍为每工作流完整T。四工作流逐一报告原始时间、配对差、时间减少和吞吐变化，不隐藏回归。

为避免测完挑有利条件，两个确认性系统比较事前定义为：P对I、P对E在四工作流等权组合上的log时间比。每block计算：

$$
g_b(P,B)=\frac14\sum_{j=1}^{4}\log\frac{T_{B,j,b}}{T_{P,j,b}},\qquad
G(P,B)=\exp\!\left(\frac1n\sum_{b=1}^{n}g_b(P,B)\right)-1.
$$

B分别为I、E；G是这些等权工作流的几何吞吐比增益，不是按请求数或token加权的总体生产收益。以完整block为单位估计区间，两个主比较的检验采用Holm校正；同时完整报告各工作流效应及未调整区间，不将其都包装为独立确认性胜利。

P��F及五个“条件×消融”对比作为分别声明的次级比较族。若据其作正式性能优越性主张，则各自校正并报告全部结果；否则以估计与机制说明为主，避免事后只挑显著项。机制计数也按启动汇总，不对26次退出做伪重复检验。

建议log比/配对差的t区间作为主要估计，完整原值和顺序供审查。符号翻转只能在相应零假设下符号可交换等假设成立时作敏感性分析，不能一概称无分布精确，也不再要求两种不同方法同时过线才准报告估计。小样本假设与范围明示。

### 8.3 样本量不是收益保证

n=8是建议的预算档位，不是对1%效应的保证。冻结前用已有同尺度方差及校准/设施诊断规划；不得用正式评价前几个block决定追加。近似计算可用n≈(z_0.975+z_0.8)²σ_pair²/δ²，再用小样本t或模拟修正。

例如σ_pair约12.5s、期望识别5s差异时，正态近似就需要约49个配对；不是跑8次便能确认约0.7%。该例仅说明代价，不能把旧W2方差当所有新工作流的真值。若预算不足以识别自适应的小效应，应事前接受不确定，或缩小问题/矩阵后重新冻结，不能测完追显著。

预算若只允许6轮，可在启动前将整套矩阵改为126次并说明精度损失；不在6轮看完后择有利条件加至8轮。等价/非劣必须另外声明实用界和功效，不由CI跨零推出。

## 9. 统一运行协议与测量注意事项

1. **正确性先行。** 每种基线/消融通过固定小样本输出检查、映射/统计一致性与配置断言。FP8允许误差按相同路径identity重复和既有校验定义，不编造跨模型统一容差。若主张模型质量不变，另用真实任务评分；固定长度压力流本身不证明任务质量。
2. **冷控制与计算预热分开。** 主实验从统一初始专家布局、空控制历史开始，保留首次布局适应成本。JIT/kernel缓存可在独立setup用校准输入预热；不能将一次已适应的完整benchmark当warmup后只测第二遍。若当前bootstrap存在统计draw，固定启动栅栏与记录语义，并在冻结前验收；无法消除时如实记初始状态，不筛选。
3. **初始化合法一致。** I/P/F逻辑主映射为identity；E冗余槽按官方初始化规则，不能给它手工不利布局，也不能给P偷偷加载evaluation最优图。若新增稳态实验，独立定义校准前缀及计时后缀，各方法同权访问。
4. **缓存与顺序。** 关闭Radix Cache以减少重复prompt混杂；若研究真实缓存部署，另开范围实验。计算缓存、文件、随机seed和请求顺序固定，客户端实际发放/完成日志保留。
5. **服务路径核对。** 记录真实prefill/decode/idle与graph使用；O1不能替代所有rank阶段检查，graph启动成功也不等于热路径replay全部成立。
6. **计时边界。** 主墙钟来自客户端统一单调钟；过程事件用单调时钟和请求ID关联。真实forward独立计数，不能用完整窗Σsteps下界作全程分母。
   TTFT必须核验客户端是否真正记录流式首token；只有完整响应时间时不能改名为TTFT。若需补客户端计时，在正式运行前独立锁版，所有臂共用，并核验记录自身不会成为吞吐瓶颈。
7. **计数口径。** r跨层取mean；record CPU、GPU核、暴露等待分开；交换批次与专家对数分开；KV容量与0.8显存池分开。所有成本留在T内，不二次扣除。
8. **采样覆盖。** n_fresh是assignment，不是独立token；S变化按真实观测更新，不能把乘S或n_min/4解释成同精度保证。样本不足事件如实报告。
9. **失败。** 所有计划启动有状态。仅零测量数据的基础设施boot可按预先有限规则重启；方法性崩溃、OOM、超时必须作为完成率和可行性结果，不当无效样本无痕删除。成功运行的T仅是条件于成功的时间，不能单独给失败方法算漂亮吞吐。
10. **不做中期选参。** 可以看运行健康和配置，禁止根据终点调整顺序、数据或样本量；作者要求查看时记录偏离，仍不改规则。运行结束统一分析。

## 10. 冗余专家与压测容量实验P1

用户明确允许EPLB使用冗余专家，并希望量化压力下可能的代价。本实验允许正、负、拐点或无明显效应，不设“冗余必然有害”的结论。

### 10.1 设计

比较P_final和官方EPLB R=0/16/32，所有EPLB使用校准选定的同一算法、周期与其他参数，只有R变化。使用真实长输入/长输出工作流，例如输入2048、输出128；目标N=2048或4096由CPU盘点冻结。

两档压力：低并发64、高并发C_hi。C_hi在查看性能终点前，依据真实KV容量与每请求token预算从{256,512,1024}选定，并由可行性smoke检查服务能正常准入。高压允许排队，不能只通过让EPLB OOM人为证明不利；统一最大running约束并报告实际排队/在飞数。

每单元4个配对block：4臂×2压力×4重复=**32次**。若主张R更大时的容量拐点，R64可另加8次，但不是默认必跑。旧主表共同KV上限与此原生容量实验不同，不混池。

### 10.2 资源条件

各方法同一8GPU与mem_fraction=0.8，允许分配其原生可用KV池。这样测量的是相同设备预算下整个方法的部署后果。报告加载后权重、运行时保留、临时迁移峰值、KV token容量；不能把增加16/128=12.5%专家槽说成总HBM增加12.5%。

由额外权重得到的静态容量减少，与动态执行、通信、统计和迁移成本分开。R变化还改变布局与副本调度，因此总时间差不是“纯冗余显存成本”。实际复制槽负载按运行计数，不按均分估计。

### 10.3 指标与结论边界

输出吞吐—并发、TTFT/完成延迟p99—并发、实际KV容量—R、错误/超时率、排队/运行请求及实际r。若已有可用SLO，事前声明阈值并报告goodput；没有阈值就不临时造一个有利SLO。

低压可能因更好均衡而受益，高压可能因容量或其他执行代价退化，也可能始终受益。只有实测与队列/容量证据一致时才讨论相应机制；不把相关性写成唯一因果解释。4次重复主要提供范围估计，小效应仍可能不确定。

## 11. 两个可选端到端扩展

### X1：同多重集、不同变化频率

复用E3同一8192请求及长度，只改变顺序。长块为原4×2048；短块为按四域每512请求循环，共16块；固定seed混洗作为快速混合参照。三种序列均在运行前冻结，控制器看不到标签。

长块已有E3；新增两序列可先只比较P/F/E，若需确认性重复按8block为48次，不默认同时扩展I与全部消融。这是明确的新范围预算，不用它寻找一条最好曲线替代主表。实际batch混合必须测量；文件切换次数不等于GPU真实变化次数。

### X2：并发与长输入敏感性

若只保留一项扩展，优先用P1容量实验覆盖并发，不另开重复网格。长输入可在真实longbench_4k上比较I/E/P，固定O32，8block共24次；它回答执行占比改变时的范围，不用于证明纯域差异。

目前没有第二模型在盘，不将多模型或EP4列为当前必做。只有论文标题/结论明确宣称泛化时才补相应配置，并保证模型确实装得下；不以旧GB200四卡结果代替H20八卡的纯EP对照。

## 12. 理论部分的最后整理：不再补无效大扫描

T1复用真实padding与近均衡反向步骤，呈现raw、padded和时间。T2复用strict/original单向干预，写readiness slack而非对称死区。T3给出不可分工作下界证明，再将经验时间预测、均衡执行参考和严格下界分图/分名报告。

时间模型参数如需独立测量，只在明确后端和形状下构造balanced-execution reference；按层求和必须说明顺序、重叠、最慢rank和是否能组合成可达布局。平均拟合不自动产生数学下界；预测越界如实保留，不裁剪或重新标成可达oracle。

T4用实测动作q/C与复用K解释停止。理论影响了哪些真实代码量必须明确：工作余量代理、有限预算、观测节奏分别列出。若某个界只用于分析而未进入代码，就写分析，不虚构在线精确时间准入。

## 14. 预算与执行顺序

### 14.1 建议预算台账

| 工作包 | 建议上限 | 备注 |
|---|---:|---|
| CPU盘点/旧证据整理/最终代码对齐 | 0 GPU服务启动 | 优先进行 |
| F0兼容与输出smoke | 不超过8次短boot | 覆盖I/P/F及官方可行配置，可合并同配置检查 |
| E*/F*校准 | 最多30次完整校准启动 | 14 EPLB+8固定筛选，最多8次前两名确认；可有条件复用 |
| M2捕获 | 建议最多4次诊断服务启动 | 原始路由小段、有容量上限，避免完整per-token长流dump |
| M4真实回放 | 最多8capture×3独立启动=24个capture级replay job | 多层若拆开，预算重新明确，不暗中乘4 |
| E1–E4＋A1–A4 | **168次**完整评价启动 | 推荐8block；6block事前替代为126次 |
| M3诊断trace | 不超过4次短诊断启动 | 独立于主表，尽量复用已需捕获的启动但保持计时界限 |
| P1资源压力 | **32次** | 若保留无复制资源主张，应安排；R64另8次可选 |
| X1/X2 | 默认0次 | 独立可选预算，不在主战役自动续跑 |

168+30+32=230次完整服务启动为完整推荐档，不含短smoke/捕获/replay；不是将每项都称“低成本”。仅按历史W1/W2每启动8.5–14.5min估算，168次约23.8–40.6h墙钟、190–325 GPU·h；新O128/压力流可能不同，不能直接承诺该范围。8卡墙钟乘8才是GPU·h。

如果预算有限，先完成CPU/M2/M4并冻结主问题，可选择6block的126次主矩阵，加30校准和32压力共188次完整启动；精度减弱须事前接受。也可将资源压力作为后续独立包，先完成主论文的系统与模块评价。不得因为“168次太多”在测完后把某些条件n2当正式确认，也不能把2h开发战役成本套到数百次。

### 14.2 顺序

1. 只读清点现有数据与配置，复用T1–T4/M1/M6，绑定当前论文主张。
2. 完成必要smoke、阶段统计与贪心CPU检查；确认消融确实改变目标机制且正确，不比较正式终点选数据。
3. 用独立校准确定E*/F*及公共容量，P参数继续冻结；给出新流实际运行时间和预算估计。
4. 冻结完整主矩阵、臂序、主/次比较、n、失败与分析规则；各内嵌臂一同排入block。
5. 一次执行E1–E4和内嵌消融，全部结果统一分析。P1可单独预注册并并行规划，但同一8卡不能同时运行干扰任务。
6. 输出论文图表、原始台账与限制。可选扩展只有在作者明确保留相应主张和预算时另行安排，不根据结果追加到显著。

## 15. 失败或不确定结果怎样收口

本方案四主流覆盖所研究的稳定/变化与prefill/decode组织，不代表所有下游任务。若正文继续声称“广泛任务普遍受益”，需将MMLU等已有负收益类型纳入范围证据并按可比性说明；不能只保留历史正向prover结果。当前范围不足时优先收紧主张，不自动追加全任务网格。

| 结果情形 | 可以写什么 | 不能写什么 |
|---|---|---|
| P优于I/E，但不优于F | PB整体有部署价值，自适应附加收益未确立 | 全部系统收益来自adaptive |
| P对F有优势，但只在部分流成立 | 明确条件下自适应有净收益，其他范围有限 | 普遍优于固定窗口 |
| 规划代理更好，真实执行不更好 | 代理/执行脱节及适用范围，O1获得进一步支持 | 算法性能已提升 |
| 行为改善但时间不确定 | 规则作用、活跃性和区间范围 | 机制正确所以必然加速 |
| E冗余低压有效、高压退化 | 相同设备预算下测得的容量/性能权衡 | 复制在所有场景无效 |
| 主系统也没有稳定优势 | 限定系统性能主张，保留机制与理论贡献并重新评估定位 | 用局部回放收益替代完整服务胜利 |

实验设计能提高可信度，不能保证得到大效应。正式评价之后，正文按结果确定贡献强度，不再靠更弱固定配置或只报有利域修补故事。
